# tg-scribe — Telegram для AI-агентов на Mac

[English](README.md) | Русский

Локальный MCP-сервер для macOS и Windows дает AI-агенту, например Claude Code, доступ к вашему аккаунту Telegram. Агент выгружает переписку в Markdown-файлы на диске и работает с ними: ищет, анализирует, пересказывает, готовит ответы.

Сервер работает на вашем компьютере и подключается к Telegram от вашего имени через официальный протокол MTProto. Для подключения используется библиотека Telethon и ваш собственный `api_id`. Распознавание текста на фото и чтение PDF, doc и rtf работают через Apple Vision, PDFKit и textutil, поэтому эти функции требуют Mac; остальное — вход, архив, поиск, отправка, пересылка, прокси — работает и на Windows.

## Что умеет

| Инструмент | Что делает |
|---|---|
| `list_dialogs` | Показывает 50 последних чатов и их папки. Остальные находит поиском по названию; `folder` оставляет только чаты одной папки |
| `list_topics` | Показывает топики форума: id и название |
| `sync_chat` | Выгружает переписку в архив: за нужное число дней или целиком. При следующих вызовах догружает новые сообщения. `topic` выгружает только один топик форума |
| `transcribe` | Расшифровывает голосовые и кружки. Нужен Telegram Premium |
| `ocr_photos` | Распознает текст на фото через Apple Vision, прямо на Mac |
| `read_files` | Читает текст файлов txt, md, csv, html, pdf, doc, docx, rtf, xlsx, pptx и картинок прямо на Mac, в том числе сканы PDF, и сохраняет его в `text/<id>.txt` в папке чата |
| `fetch_media` | Скачивает фото или файл до 50 МБ, чтобы агент посмотрел на него сам. Файл сохраняет имя: `<id>_<имя>`. Видео и аудио не скачивает |
| `describe_media` | Сохраняет в архив короткое описание фото или файла |
| `fetch_large_file` | Скачивает файл больше 50 МБ после вашего подтверждения. Большой файл качается за несколько вызовов |
| `send_message` | Отправляет сообщение после вашего подтверждения |
| `forward_messages` | Пересылает сообщения в другой чат после вашего подтверждения |

### Как это выглядит

1. Вы спрашиваете: «О чем договорились в чате с прорабом за последние три недели?»
2. Агент вызывает `sync_chat` с `days=21`. Сервер выгружает в архив три недели переписки, от новых сообщений к старым.
3. Агент ищет по архиву нужные сообщения. Важное голосовое помечено «не расшифровано» — агент расшифровывает его через `transcribe`. На фото сметы нужны цифры — агент распознает текст через `ocr_photos`.
4. Агент отвечает и ссылается на id сообщений.
5. На следующий день вы спрашиваете: «Что нового?» `sync_chat` догружает только новые сообщения. Голосовые, фото и файлы до 10 МБ в них сервер обрабатывает сразу, до 20 штук каждого вида за вызов. Файлы больше ждут `read_files`.
6. Вы спрашиваете: «А что решили в прошлом месяце?» Агент вызывает `sync_chat` с `days=60`, и сервер догружает недостающую старую историю.

Голосовые, фото и файлы из старой истории сервер не обрабатывает при выгрузке. Агент расшифровывает, распознает и читает их, только когда они нужны для задачи. Поэтому выгрузка занимает минуты, а не часы, и не тратит лимиты.

## Архив

Переписка лежит в папке `archive/` рядом с исходным кодом MCP, по одному файлу на месяц. Текст прочитанных файлов — там же, в подпапке `text/` каждого чата. Папка внесена в `.gitignore`.

Топик форума, выгруженный с `topic`, лежит в своей папке внутри папки чата: `archive/<чат>/<топик>__<id_топика>/2026-10.md`.

```
archive/Иван-Петров__123456789/2026-10.md
```

Одна строка — одно сообщение. Пример файла:

```
[2026-10-31 14:02] #48213 Иван Петров: Скинул смету
[2026-10-31 14:03] #48214 Иван Петров [фото, с текстом]: 
  [на фото] Плитка: 48 000 ₽
  [на фото] Итого: 120 000 ₽
[2026-10-31 14:05] #48215 Я ↩48213: [голосовое 0:42] «Дорого, давай обсудим вечером»
[2026-10-31 14:06] #48216 Иван Петров [фото: план кухни с размерами]: вот план
[2026-10-31 14:07] #48217 Иван Петров [переслано из «Ремонт без боли»]: Цены на плитку
  с ноября выросли на 15%
[2026-10-31 14:10] #48218 Иван Петров: [кружок 0:35, не расшифровано]
[2026-10-31 14:12] #48219 Иван Петров [файл договор.docx, 48 КБ, с текстом]: подпиши
```

Что означают элементы строки:

| Элемент | Значение |
|---|---|
| `[2026-10-31 14:02]` | Дата и время по часовому поясу вашего Mac |
| `#48213` | id сообщения |
| `Я` | Вы |
| `↩48213` | Ответ на сообщение 48213 |
| Строка с отступом в 2 пробела | Продолжение многострочного сообщения |
| `[переслано из «…»]` | Пересланное сообщение и его источник |
| `[голосовое 0:42] «…»`, `[кружок 0:35] «…»` | Расшифровка голосового или кружка |
| `[голосовое 1:10, не расшифровано]` | Голосовое еще не расшифровано |
| `[фото]` | Фото еще не обработано |
| `[фото, с текстом]` | На фото есть текст, он в строках `[на фото]` ниже |
| `[фото, без текста]` | На фото нет текста |
| `[фото: …]`, `[фото, с текстом: …]` | Описание фото, которое сохранил агент |
| `[фото, недоступно]` | Фото удалено из Telegram |
| `[фото, не читается]` | Файл фото поврежден |
| `[файл report.pdf, 2.3 МБ]` | Файл. У txt, md, csv, html, pdf, doc, docx, rtf, xlsx, pptx и картинок — еще не прочитан |
| `[файл …, с текстом]` | Весь текст файла лежит в `text/<id>.txt` в папке чата, а не в файле месяца: агент не тратит на него токены, пока файл не нужен |
| `[файл …, без текста]` | В файле нет текста |
| `[файл …, 12 стр., …]` | Число страниц PDF, появляется после чтения |
| `[файл …, скан, …]` | Часть страниц PDF — сканы: их текст распознан через Apple Vision, в нем возможны ошибки |
| `[файл …: …]`, `[файл …, с текстом: …]` | Описание файла, которое сохранил агент. Оно не заменяет отметку: непрочитанный файл `read_files` все равно прочитает |
| `[файл …, недоступно]`, `[файл …, не читается]` | Файл удален из Telegram или поврежден |
| `[файл …, слишком большой]` | Файл больше 50 МБ, сервер его не скачивает |
| `[видео]`, `[стикер 👍]`, `[gif]`, `[опрос]`, `[геопозиция]`, `[контакт]` | Другие вложения |

Архив только пополняется: изменения и удаления сообщений в Telegram в него не попадают.

## Что понадобится

- macOS или Windows. Вход, архив, поиск, отправка, пересылка и прокси работают на обеих системах; распознавание текста на фото и чтение PDF, doc и rtf требуют macOS (Apple Vision, PDFKit, textutil).
- [uv](https://docs.astral.sh/uv/) — он сам ставит Python 3.12 и все зависимости, включая `python-socks` для соединений через прокси.
- AI-агент с поддержкой MCP, например [Claude Code](https://claude.com/claude-code).
- Аккаунт Telegram. Для расшифровки голосовых нужен Telegram Premium.

## Установка

### 1. Скачайте проект и поставьте зависимости

Поставьте [uv](https://docs.astral.sh/uv/), если его еще нет:

- macOS: `brew install uv` или официальный установщик `curl -LsSf https://astral.sh/uv/install.sh | sh`
- Windows (PowerShell): `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`

Затем скачайте проект и поставьте зависимости:

```bash
git clone https://github.com/rodion1010/tg-scribe.git tg-scribe
cd tg-scribe
uv sync
```

`uv sync` сам скачивает Python 3.12 и ставит все зависимости — Telethon, библиотеку MCP, `segno` для QR-кода входа, `python-socks` для соединений через прокси. Ничего вручную ставить не нужно.

### 2. Получите api_id и api_hash

Telegram пускает сторонние программы в аккаунт только через зарегистрированное приложение. Регистрация бесплатная и занимает пару минут.

1. Откройте [my.telegram.org](https://my.telegram.org) и введите номер телефона в международном формате, например `+79991234567`.
2. Введите на сайте код подтверждения. Он придет в Telegram от аккаунта «Telegram», а не по СМС.
3. Выберите **API development tools**.
4. Заполните поля:
   - **App title** — любое название без слова «Telegram», например `tgc`. Слово «Telegram» в названии запрещают правила API.
   - **Short name** — от 5 до 32 латинских букв и цифр, например `tgclaude`.
   - **URL** — оставьте пустым.
   - **Platform** — Desktop.
   - **Description** — оставьте пустым.
5. Нажмите **Create application**. На странице появятся **App api_id** — число и **App api_hash** — строка из 32 символов.

Если сайт показывает `ERROR`, откройте его в другом браузере. На один аккаунт можно создать одно приложение: если оно уже есть, сайт сразу покажет его данные.

Никому не показывайте api_hash и не коммитьте его: с ним можно выдавать себя за ваше приложение.

### 3. Сохраните api_id и api_hash в конфиг

Создайте папку и файл конфига:

```bash
mkdir -p ~/.tgc && chmod 700 ~/.tgc
nano ~/.tgc/config.toml
```

Вставьте в файл свои значения:

```toml
api_id = 12345678
api_hash = "0123456789abcdef0123456789abcdef"
```

Закройте доступ к файлу для других пользователей:

```bash
chmod 600 ~/.tgc/config.toml
```

### 4. Войдите в аккаунт

```bash
uv run python -m tgc.login
```

Программа покажет QR-код — отсканируйте его в Telegram: **Настройки → Устройства → Подключить устройство**. Код открывается как PNG в программе для просмотра картинок по умолчанию; добавьте `--terminal`, чтобы показать код прямо в терминале. Код живёт около 26 секунд и автоматически показывается заново. Если включена двухэтапная проверка, программа спросит облачный пароль. После входа появится файл `~/.tgc/tgc.session`.

Этот файл дает полный доступ к вашему аккаунту без кода и пароля. Не копируйте его, не публикуйте и не кладите в облако. Если файл утек, завершите сеанс в Telegram: **Настройки → Устройства**.

### 5. Подключите сервер к агенту

Сервер запускается командой:

```bash
uv run --directory /путь/к/tg-scribe python -m tgc.server
```

Здесь `/путь/к/tg-scribe` — папка, куда вы скачали проект. Добавьте эту команду в настройки MCP-серверов вашего агента. Ниже описано подключение к Claude Code, OpenChamber (OpenCode) и Hermes Agent.

#### Claude Code

В проекте уже есть `.mcp.json` с этим сервером. Запустите Claude Code в папке проекта и разрешите сервер `tg`, когда Claude Code спросит.

Чтобы Telegram был доступен из любой папки, подключите сервер для своего пользователя:

```bash
claude mcp add tg --scope user -- uv run --directory /путь/к/tg-scribe python -m tgc.server
```

Архив и в этом случае лежит в `archive/` рядом с исходным кодом MCP.

Правила подтверждения отправки и скачивания больших файлов из `.claude/settings.json` проекта в других папках не действует. Добавьте их в `~/.claude/settings.json`:

```json
{
  "permissions": {
    "ask": ["mcp__tg__send_message", "mcp__tg__forward_messages", "mcp__tg__fetch_large_file"]
  }
}
```

#### OpenChamber и OpenCode

1. Добавьте сервер. Команда работает из любой папки; `--global` включает сервер во всех проектах:

```sh
opencode mcp add tg --global -- uv run --directory /путь/к/tg-scribe python -m tgc.server
```

Команда сама записывает сервер в конфиг — обычно `~/.config/opencode/opencode.json`.

2. Проверьте подключение:

```sh
opencode mcp list
```

`✓ tg connected` — сервер работает. В самом приложении серверы и их состояние показывает `/mcps`.

Или добавьте сервер в конфиг руками:

```jsonc
{
  "mcp": {
    "tg": {
      "type": "local",
      "command": ["uv", "run", "--directory", "/путь/к/tg-scribe", "python", "-m", "tgc.server"]
    }
  }
}
```

3. Включите подтверждение отправки, пересылки и скачивания больших файлов. OpenCode по умолчанию разрешает все инструменты и аннотацию `readOnlyHint` не учитывает, поэтому без этих правил агент отправит сообщение, не спросив. Добавьте в тот же конфиг:

```jsonc
{
  "permissions": [
    { "action": "tg_send_message", "resource": "*", "effect": "ask" },
    { "action": "tg_forward_messages", "resource": "*", "effect": "ask" },
    { "action": "tg_fetch_large_file", "resource": "*", "effect": "ask" }
  ]
}
```

Если в конфиге уже есть правила `allow`, поставьте эти после них: срабатывает последнее подходящее правило. Это формат конфига V2; в старых версиях OpenCode ключ назывался `permission`, сверьтесь с [документацией](https://opencode.ai/docs/permissions/) своей версии.

4. Спросите агента: «Покажи мои последние чаты в Telegram». Инструменты называются `tg_list_dialogs`, `tg_send_message` и так далее.

#### Hermes Agent

1. Добавьте сервер. В `--command` нужен полный путь к `uv` — узнайте свой через `which uv`:

```sh
hermes mcp add tg --command /opt/homebrew/bin/uv --args run --directory /путь/к/tg-scribe python -m tgc.server
```

На вопрос Hermes о включении инструментов ответьте «y».

2. Проверьте подключение:

```sh
hermes mcp test tg
```

3. Включите подтверждение отправки и пересылки. В `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  tg:
    trust: untrusted
```

Инструменты чтения после этого работают без вопросов — сервер помечает их аннотацией `readOnlyHint`. `send_message`, `forward_messages` и `fetch_large_file` спрашивают каждый раз: Allow Once, Allow Session или Allow Always. «Allow Always» записывает инструмент в `command_allowlist` в том же файле — уберите строку, чтобы отозвать разрешение.

4. Перезапустите Hermes или выполните `/reload-mcp` в открытой сессии.

### 6. Проверьте подключение

Спросите агента: «Покажи мои последние чаты в Telegram». Он вызовет `list_dialogs` и покажет список.

## Разрешения

Агент отправляет и пересылает сообщения только после вашего подтверждения. Инструменты разделены аннотациями: каждый инструмент, который только читает — список чатов, выгрузка архива, расшифровка, распознавание текста и файлов, — помечен аннотацией `readOnlyHint`, поэтому агенты вызывают его без вопросов. У `send_message`, `forward_messages` и `fetch_large_file` пометки нет: агенты, которые понимают эту аннотацию, например Hermes, запрашивают подтверждение на каждый вызов. Аннотация — только подсказка: агенту, который ее не учитывает, например OpenCode, нужны явные правила подтверждения, как в инструкции выше.

В Claude Code это обеспечивает файл `.claude/settings.json`: он разрешает читать чаты, выгружать их и распознавать медиа без вопросов, а на отправку и пересылку ставит правило `ask`. Claude Code каждый раз показывает текст и чат и ждет вашего «да». Не переносите `send_message` и `forward_messages` в `allow`.

Так же, через `ask`, работает `fetch_large_file`: файл больше 50 МБ скачивается, только если вы согласились. Это защищает от того, что агент займет диск и время ненужным файлом.

Правило действует только в папке проекта. Для других папок добавьте его в `~/.claude/settings.json`, как описано в шаге 5. В других агентах настройте подтверждение для `send_message` так же.

## Как указать чат

Чат можно назвать по части названия, но поиск Telegram находит не все чаты, и агент может выбрать похожий. Перед отправкой надежнее указать id чата: его показывает `list_dialogs`. После отправки сервер называет чат, куда ушло сообщение.

Чтобы видеть id прямо в Telegram, включите его показ в отладочном меню. В Telegram Desktop откройте **Настройки → Продвинутые настройки → Экспериментальные настройки** и включите **Show Peer IDs in Profile**. Как открыть отладочное меню на других платформах, описано в [инструкции tginfo](https://tginfo.me/open-debug-menu/).

Меняйте в отладочном меню только эту настройку: другие пункты могут сломать приложение или удалить секретные чаты.

## Топики форумов

Некоторые супергруппы — форумы: чат разбит на топики. `list_topics` показывает их с id.

- Чтобы читать один топик, агент вызывает `sync_chat` с `topic` — id топика или часть названия, как у чата. Пример: «Что ответили про GPT Model Hub за неделю?» → `sync_chat` с `days=7` и `topic="GPT Model Hub"`.
- Топик выгружается в свою папку внутри папки чата: `archive/<чат>/<топик>__<id>/`. Выгрузка топика не трогает файлы самого чата.
- `transcribe`, `ocr_photos`, `read_files`, `fetch_media`, `fetch_large_file` и `describe_media` принимают такой же `topic`, когда работают с сообщениями топика, — голосовые, фото и файлы попадают в папку топика.
- Без `topic` выгружается весь форум, все топики вперемешку в файлах чата.

## Прокси

По умолчанию сервер подключается к Telegram напрямую. Если Telegram доступен только через прокси, укажите его в `~/.tgc/config.toml`:

```toml
proxy = "socks5://127.0.0.1:1080"
```

- **Явный прокси.** Схемы: `socks5://`, `socks4://`, `http://`, `https://` (используется как HTTP CONNECT) и MTProto-прокси Telegram: `mtproto://хост:порт/секрет`. Схему можно не указывать: `127.0.0.1:1080` означает `https://127.0.0.1:1080`. Логин и пароль — в URL: `socks5://user:pass@host:port`. Символы `@`, `:` и `/` в логине или пароле записываются как `%40`, `%3A` и `%2F`.
- **`proxy = "auto"`** — сервер сам ищет прокси: переменные окружения `http_proxy`/`https_proxy`, затем настройки ОС — Windows: свойства браузера/сеть, macOS: Системные настройки → Сеть → Прокси. Ничего не нашлось — подключение напрямую.
- **`proxy = "direct"`** — подключаться напрямую, то же, что убрать строку.

При старте сервер пишет метод подключения в лог, например: `Telegram: подключаюсь напрямую (proxy в config.toml не задан)` или `Telegram: подключаюсь через прокси socks5://127.0.0.1:1080 (из config.toml)`.

## Ограничения и риски

- **Лимиты Telegram.** Если Telegram просит подождать дольше 30 секунд, сервер останавливается и сообщает, сколько ждать. Дольше 30 секунд он сам не ждет, чтобы не упасть по таймауту.
- **Большие выгрузки** идут за несколько вызовов: каждый работает до 200 секунд. 150 тысяч сообщений загрузятся примерно за 10 вызовов, агент повторяет их сам.
- **Одна сессия за раз.** Если две сессии агента обращаются к Telegram одновременно, вторая получит ответ «Telegram занят» и повторит позже.
- **Правила Telegram.** [Условия API](https://core.telegram.org/api/terms) запрещают мешать исчезновению самоуничтожающихся сообщений, а сервер сохраняет в архив сообщения из чатов с автоудалением. [Условия лицензирования контента](https://telegram.org/tos/content-licensing) запрещают обучать модели ИИ на данных Telegram. В архиве есть и чужие сообщения, поэтому запретите провайдеру агента обучать модели на ваших данных. В claude.ai это настройка **Help improve Claude**.
- **Текст из чатов — данные, а не команды.** Сервер просит агента не выполнять просьбы из переписки. Подтверждайте отправку, только когда прочитали текст.

## Разработка

Запустите тесты:

```bash
uv run pytest
```

Код разделен на четыре модуля:

- `tgc/client.py` — подключение к Telegram и поиск чата;
- `tgc/archive.py` — формат архива, синхронизация, расшифровка и распознавание;
- `tgc/server.py` — MCP-инструменты и инструкции для агента;
- `tgc/login.py` — вход в аккаунт.
